# Phase 2 — Gap Register & Build Plan

Ranked by **(Severity × Revenue Impact) ÷ Effort**. Legal/platform-risk items are CRITICAL regardless of revenue (protocol R4/R5). "Fixed 09-16" items were closed during this audit session (see Phase 1, E-table).

## 1. Assumptions (explicit)

- A1. Inkforge is KDP-first, English-first, single team (1–3 builders); multi-tenant SaaS is a later revenue line, not day-1.
- A2. The frozen "core" today = `packages/core` (book model, humanize engine incl. `POLISH_SYSTEM` prompt, formatting, EPUB export) — additive wrappers only, per protocol R1.
- A3. Postgres is the only durable store; jobs run in-process in forge (no external queue) until scale demands otherwise.
- A4. Revenue model to be confirmed (see Open Questions); ranking below assumes direct-author SaaS first, agency white-label second.
- A5. `SPECULATIVE` items carry confidence labels; `PROHIBITED` items are flagged inline (fake reviews/impersonation — will never be built).

## 9. Rollback plan

- Git: two commits created this session (scaffold snapshot → audit + wiring). `git revert <sha>` reverts cleanly.
- Migrations (G-07) ship forward-only with documented down scripts; schema changes are additive.
- Feature flags: `ALLOW_*` and `PUBLIC_FALLBACK_ENABLED` already gate risky paths (config); new modules ship behind the same flags.
- EPUBCheck is fail-soft (skips w/o Java) — validation regressions cannot block exports, only warn.
- Every repaired dependency pin is a registry-verified version; rollback = restore pin in package.json + reinstall.
